### BE-1. Seeded Counts vs Real Like Records

#### Root Cause
Initial mock seeds hardcoded `likeCount: 8` or `12` without seeding corresponding `FeedLike` documents. When users toggled likes, `likePost` performed count recalibration which reset the count to 1 or 0.

#### Resolution
1. The seeding script (`src/scripts/seed-feed.js`) now creates authentic `FeedLike` documents matching all seeded post and comment like counts.
2. In `src/controllers/feed.controllers.js`, like and unlike operations use atomic `$inc` operations (`{ $inc: { likeCount: 1 } }` and `{ $inc: { likeCount: -1 } }`) alongside `FeedLike.findOneAndUpdate` upserts/deletes.
3. Both `PUT` (like) and `DELETE` (unlike) return the current `likeCount` in the response envelope so the client can update its local store directly.

## 4. P1 — Unclear Behavior & Deep Dive Answers

### BE-6. Cascade Deletes & Counter Behavior

1. **Deleting a Post (`DELETE /api/v1/feed/posts/:id`):**
   - The post document is soft-deleted (`isDeleted: true`, `deletedAt: new Date()`).
   - The server triggers `FeedComment.updateMany({ postId: post._id }, { $set: { isDeleted: true } })`.
   - Existing `FeedLike` and `Report` records are kept for audit logs, but the post immediately drops out of all feed queries (`isDeleted: false`).
2. **Deleting a Top-Level Comment (`DELETE /api/v1/feed/comments/:id`):**
   - The comment is soft-deleted.
   - Child replies are cascade soft-deleted (`FeedComment.updateMany({ parentId: comment._id }, { $set: { isDeleted: true } })`).
   - The post's total comment count is decremented by `1 + childRepliesCount`:
     ```javascript
     const childCount = await FeedComment.countDocuments({ parentId: comment._id });
     await FeedPost.updateOne({ _id: comment.postId }, { $inc: { commentCount: -(1 + childCount) } });
     ```
3. **Deleting a Nested Reply (`DELETE /api/v1/feed/comments/:id`):**
   - The reply is soft-deleted.
   - The parent comment's `replyCount` is decremented by `1` (`{ $inc: { replyCount: -1 } }`).
   - The parent post's `commentCount` is decremented by `1` (`{ $inc: { commentCount: -1 } }`).

### BE-7. Block, Mute, and Member State

1. **Blocking a Member:**
   - Call existing `POST /api/v1/blocks/:userId`.
   - A block is mutual. The server's `getFeedBlockAndMuteIds` excludes all blocked user IDs from post lists, searches, comments, and profile queries (`authorId: { $nin: [...blockedIds, ...mutedIds] }`).
2. **Unblocking a Member:**
   - Call existing `DELETE /api/v1/blocks/:userId`.
3. **Muting / Unmuting Feed Content:**
   - To mute posts: `PUT /api/v1/feed/users/:userId/mute` (returns `{ muted: true }`).
   - To unmute: `DELETE /api/v1/feed/users/:userId/mute` (returns `{ muted: false }`).
   - To list all muted members: `GET /api/v1/feed/mutes` (returns `{ items: [Author] }`).
4. **Member State on Feed Profile:**
   - `GET /api/v1/feed/users/:userId` now includes:
     ```json
     {
       "isMuted": false,
       "isBlocked": false,
       "messageAction": "chat",
       "conversationId": "6af5623746ff650a1912952a"
     }
     ```
5. **Safe Reporting Sandbox:**
   - Call `POST /api/v1/reports`.
   - For posts: `{ "targetType": "post", "postId": "<id>", "reason": "inappropriate_content", "description": "..." }`
   - For comments: `{ "targetType": "comment", "commentId": "<id>", "reason": "harassment", "description": "..." }`
   - For members: `{ "targetType": "feedUser", "reportedUserId": "<id>", "reason": "spam", "description": "..." }`
   - **Sandbox Safe Target:** The seeded deleted post (`ID: 6af81df64eefc4720a1953e0`) is a safe target for integration testing. If a user submits duplicate reports on the same target, the server safely responds with `409` and does not crash or corrupt data.

### BE-8. "For you" Paging & Cursor Mechanics

- **Seeded Data:** The dev server has been seeded with **65+ active posts**, **25 top-level comments**, and **6 nested replies**.
- **Paging Stability:**
  - `For you` ranking sorts by `{ likeCount: -1, commentCount: -1, _id: -1 }`.
  - Paging uses an opaque cursor encoding the seek offsets. The server executes cursor-based `$lt` queries.
  - When reaching the end of the feed, `hasMore` is `false` and `nextCursor` is `null`.
  - Automated tests confirm zero item overlap or item skipping across consecutive pages.

### BE-9. Universal & App Links Support

1. **Android App Links:** Hosted at `GET /.well-known/assetlinks.json`.
2. **iOS Universal Links:** Hosted at `GET /.well-known/apple-app-site-association`.
3. **Web Preview Fallback:**
   - Navigating to `https://findanikah.app/feed/post/:id` or `/feed/u/:id` in a web browser serves a responsive HTML page with:

     - App banner directing the user to launch the mobile app or install from the App Store / Play Store.

### BE-10. View Count Deduplication

1. **Batching:** Send `POST /api/v1/feed/posts/views` with `{ "postIds": ["..."] }`.
2. **Deduplication Window:** Views are deduplicated per user per post within a **1-hour rolling window**. If an impression was recorded at 10:00 AM, a subsequent open at 10:20 AM will not increment the counter.
3. **Self-Views Excluded:** When an author views or opens their own post, the server ignores the view request (`viewed: 0`).

### BE-11. Messaging from Feed Profile (`messageAction`)

`GET /api/v1/feed/users/:userId` evaluates member entitlements and match status, returning a definitive directive:

```json
{
  "messageAction": "chat",
  "conversationId": "6af5623746ff650a1912952a",
  "isMatch": true,
  "matchId": "6af5623746ff650a19129529"
}
```

| `messageAction` Value | Condition | Mobile UI Action |
| :--- | :--- | :--- |
| `"chat"` | Active match exists OR user has premium pre-match messaging entitlement | Open chat directly using `conversationId`. |
| `"compliment"` | Unmatched free user | Open the compliment / first-message bottom sheet. |
| `"upgrade"` | Out of compliments or premium messaging required | Open premium subscription paywall sheet. |
| `"none"` | Blocked or self | Hide or disable the Message button. |

### BE-14. People Search Tab

- **Endpoint:** `GET /api/v1/feed/search?type=people&q=<query>`
- **Minimum Query Length:** 2 characters.
- **Search Logic:** Case-insensitive substring matching against `fullName` and `handle`. Excludes blocked and muted accounts.
- **Payload:** Returns `{ items: [Author] }` where each author includes `isFollowing: boolean`.

- **Error Response:** `429 Too Many Requests`
```json

  "code": "RATE_LIMITED",
  "message": "You are posting comments too quickly. Please wait before commenting again.",
  "success": false
```

### BE-17. Mentions Auto-Parsing from `@handle`

The comment creation endpoint (`POST /api/v1/feed/posts/:id/comments`) parses the comment body with the regex `@([a-z0-9_]+)`.
- If a handle is detected (e.g. `@khalil_k2210`), the server automatically looks up the user and populates `mention: { userId, handle }`.
- If `mentionUserId` is passed explicitly in the JSON request body, it takes precedence.
