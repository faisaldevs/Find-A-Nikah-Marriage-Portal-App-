## 1. Chat State & Blocking Contract (`canMessage` & `blockedBy`) — P0

Every conversation object returned by:
- `GET /api/v1/conversations` (list)
- `GET /api/v1/conversations/:id` (details)
- `POST /api/v1/conversations/:userId` (open thread)

now includes:

```json
{
  "canMessage": false,
  "blockedBy": "them"
}
```

### Fields Definition
1. `canMessage` (`boolean`):
   - `true`: Conversation is active, unblocked, and eligible for messaging.
   - `false`: Either participant blocked the other, OR the match has ended (`status !== "active"`).
2. `blockedBy` (`"them" | "me" | null`):
   - `"them"`: The other member blocked the authenticated user.
   - `"me"`: The authenticated user blocked the other member.
   - `null`: Neither member blocked the other (e.g. normal chat or unmatch only).
3. **Presence suppression for `"them"`:**
   - When `blockedBy === "them"`, the `partner` object returns `isOnline: false` and `lastActiveAt: null`.
   - Real-time `presence` socket broadcasts from the blocker are suppressed and never delivered to the blocked user.

### Realtime Socket Event (`conversation:updated`)
When an **unmatch**, **block**, or **unblock** occurs, the backend immediately emits `conversation:updated` to both participants:

```javascript
socket.on("conversation:updated", ({ conversationId, canMessage, blockedBy }) => {
  // Mobile app: If current room == conversationId, instantly show or remove the "can't message" bar
  console.log("Conversation state changed:", { conversationId, canMessage, blockedBy });
});
```

## 2. Unmatch / Block / Unblock Behaviour Confirmations — P1

| Scenario | Server Behaviour & Contract |
| :--- | :--- |
| **Unmatch** (`DELETE /matches/:id`) | - Message sending immediately returns `403 "This match has ended"`.<br>- Conversation row updates to `canMessage: false, blockedBy: null`.<br>- Appears in `GET /matches/unmatched` and `GET /matches?status=unmatched` for both users.<br>- Emits `conversation:updated` to both participants. |
| **Block** (`POST /blocks/:userId`) | - Blocker's inbox list drops the conversation from `GET /conversations`.<br>- Blocked user retains the conversation in `GET /conversations` with `canMessage: false, blockedBy: "them"`.<br>- Blocker's `isOnline` is forced to `false` and `lastActiveAt` to `null`.<br>- Sends return `403 "You cannot message this member"`.<br>- Emits `conversation:updated` to both participants. |

| **Re-match after unmatch** | **Same conversation is reused (history kept).**<br>When reciprocal likes occur again, `ensureMatch` re-activates the existing match (`status: "active"`) and links to the existing `conversationId`. Previous chat history is preserved. |

## 3. Delete For Everyone — P1

The client can delete a message for both users within a 1-hour window:

### Endpoint
`DELETE /api/v1/messages/:id?scope=everyone` (or body `{ "scope": "everyone" }`)

### Rules & Responses
1. **Sender Only:** If a receiver attempts to delete for everyone, returns `403 "Only the sender can delete for everyone"`.
2. **1-Hour Window:** If `Date.now() - createdAt > 1 hour`, returns:
   ```json
   {
     "statusCode": 403,
     "success": false,
     "message": "Too late to delete for everyone",
     "code": "DELETE_WINDOW_EXPIRED"
   }
   ```
3. **Database Changes:** Sets `deletedForEveryone: true`, blanks `text: ""`, `attachmentUrl: null`.
4. **Conversation Preview:** If the deleted message was the latest message in the conversation, `lastMessagePreview` is automatically recalculated from the previous non-deleted message.
5. **Real-time Socket Event:** Emitted to **both** participants:
   ```javascript
   socket.on("message:deleted", ({ conversationId, messageId }) => {
     // Local store marks message as deleted or removes it from view
   });
   ```
6. **Payload in `GET .../messages`:** Message object contains `"deletedForEveryone": true`, `"text": ""` and populated `replyTo.deletedForEveryone: true`.

## 1. System Overview & Architecture

The chat system is built on **Node.js/Express** and **Socket.IO** with **MongoDB/Mongoose**. It supports:
- Direct 1-on-1 conversations between matched/entitled profiles.
- Message status lifecycle: **Sent &rarr; Delivered &rarr; Seen/Read**.
- Per-user conversation archiving (archiving an inbox thread on User A's side does not hide it for User B).
- Sender/Receiver side message deletion (deleting for myself blanks text for me without deleting for the recipient).
- Real-time instant messaging, typing indicators, room management, and push notification triggers.

### Base URLs
- **REST API Base URL:** `http://localhost:5001/api/v1` *(or production host `/api/v1`)*
- **Socket.IO URL:** `http://localhost:5001` *(transports: `["websocket"]`)*

### Authentication
Every HTTP request and Socket.IO connection must provide a valid JWT access token:
- **HTTP Header:** `Authorization: Bearer <access_token>`
- **Socket.IO Handshake:** `auth: { token: "<access_token>" }`

## 2. Data Models & Status Definitions

### Message Lifecycle States

| State | DB Properties | UI Indicator Example | Description |
| :--- | :--- | :--- | :--- |
| **Sent** | `isDelivered: false`, `isSeen: false`, `isRead: false` | Single grey tick (✓) | Message is saved in DB; recipient has not yet received it. |
| **Delivered** | `isDelivered: true`, `deliveredAt: <Date>` | Double grey ticks (✓✓) | Message reached recipient's device/client (or receiver is online). |
| **Seen / Read** | `isSeen: true`, `isRead: true`, `seenAt: <Date>`, `readAt: <Date>` | Double blue ticks (✓✓) | Recipient opened the thread or viewed the message. |

> **Auto-Delivery Feature:** If the message receiver is currently online on Socket.IO when a message is sent, `isDelivered` is automatically initialized to `true` with `deliveredAt: new Date()`.

### Message Schema Attributes
```typescript
interface IMessage {
  _id: string;                      // ObjectId
  conversationId: string;           // ObjectId reference to Conversation
  senderId: string;                 // ObjectId of sender
  receiverId: string;               // ObjectId of recipient
  messageType: "text" | "image" | "audio" | "system"; // Type of message
  text?: string;                    // Max 5000 chars (empty if deleted for current user or everyone)
  attachmentUrl?: string;           // File URL if image/audio message
  attachmentStorageKey?: string;    // Local disk filename
  durationSeconds?: number | null;  // For audio messages (1 to 120 seconds)
  replyToId?: string;               // ObjectId of message being quoted/replied to
  replyTo?: {                       // Populated quoted message summary
    _id: string;
    senderId: string;
    messageType: "text" | "image" | "audio";
    text?: string;
    attachmentUrl?: string | null;
    durationSeconds?: number | null;
    deletedForMe?: boolean;
    deletedForEveryone?: boolean;
  } | null;
  status: "sent" | "delivered" | "seen"; // Unified delivery status enum
  isDelivered: boolean;             // Delivery state
  deliveredAt?: string | null;      // ISO Date
  isRead: boolean;                  // Read state
  readAt?: string | null;           // ISO Date
  isSeen: boolean;                  // Seen state (synced with isRead)
  seenAt?: string | null;           // ISO Date (synced with readAt)
  deletedBy?: string[];             // Array of UserIds who deleted for themselves
  deletedForMe?: boolean;           // True if caller deleted this message
  deletedForEveryone?: boolean;     // True if sender recalled/deleted for everyone within 1 hour
  createdAt: string;                // ISO Date
  updatedAt: string;                // ISO Date
}
```

### Conversation Schema Attributes
```typescript
interface IConversation {
  _id: string;                      // ObjectId
  participants: IUser[];            // [UserA, UserB] populated with fullName, isVerified, gender, photoUrl

  partner?: {                       // Enriched partner summary
    _id: string;
    fullName: string;
    isVerified: boolean;
    gender: string;
    photoUrl?: string | null;
    isOnline?: boolean;             // Real-time online status (hidden as false if partner blocked caller or hid status)
    lastActiveAt?: string | null;   // Timestamp of last activity (hidden as null if partner blocked caller or hid status)
  };
  createdAt: string;
  updatedAt: string;
```

## 4. Real-time Socket.IO Protocol

### Connection Initialization

```javascript
import { io } from "socket.io-client";

const socket = io("http://localhost:5001", {
  auth: {
    token: userAccessToken, // JWT Access Token
  },
  transports: ["websocket"],
});

socket.on("connect", () => {
  console.log("Connected to Realtime Chat Socket");
});
```

---

### Real-time Events Matrix

#### 1. Join / Leave Conversation Room
- **Join Room:**
  ```javascript
  socket.emit("conversation:join", { conversationId: "6af42f605b5425f72fb3a7dd" }, (ack) => {
    // ack: { success: true }
  });
  ```
- **Leave Room:**
  ```javascript
  socket.emit("conversation:leave", { conversationId: "6af42f605b5425f72fb3a7dd" }, (ack) => {
    // ack: { success: true }
  });
  ```

#### 2. Real-time Message Send
- **Emit:** `message:send` *(or `send_message`)*
  ```javascript
  socket.emit(
    "message:send",
    {
      conversationId: "6af42f605b5425f72fb3a7dd",
      text: "Salam! Are you free to talk?",
      replyToId: "6af42f615b5425f72fb3a7e0" // Optional quoted message ID
    },
    (ack) => {
      if (ack.success) {
        console.log("Message sent successfully:", ack.message);
      }
    }
  );
  ```

#### 3. Real-time Message Receive (Receiver Only)
- **Listen:** `message:new`
  ```javascript
  socket.on("message:new", (message) => {
    console.log("New message incoming:", message);
    // message contains: _id, text, senderId, receiverId, replyTo, createdAt, etc.
    // 1. Append message to chat state
    // 2. Automatically acknowledge delivery if conversation is open:
    socket.emit("message:delivered", { messageId: message._id });
  });
  ```

#### 4. Cross-Device Synchronization (Sender's Other Devices)
- **Listen:** `message:sent`
  ```javascript
  socket.on("message:sent", (message) => {
    // Emitted to the sender's OTHER open devices/tabs (not the one that sent it)
    console.log("Message sent from another session:", message);
  });
  ```

#### 5. Delivered Receipt (Sent to Sender Only)
- **Emit (Recipient tells server):**
  ```javascript
  // By single message:
  socket.emit("message:delivered", { messageId: "6af42f615b5425f72fb3a7e5" }, (ack) => {});
  // OR by entire conversation:
  socket.emit("message:delivered", { conversationId: "6af42f605b5425f72fb3a7dd" }, (ack) => {});
  ```
- **Listen (Sender receives update):**
  ```javascript
  socket.on("message:delivered", (receipt) => {
    // receipt: {
    //   conversationId: "...",
    //   messageIds: ["..."],
    //   messageId: "...",
    //   by: "<userId who received it>",
    //   at: "<ISO timestamp>"
    // }
    console.log("Message(s) delivered:", receipt.messageIds);
    // Update matching local message status to double grey ticks (✓✓)
  });
  ```

## 5. Client Implementation Best Practices

### A. Message Status Icon Logic (WhatsApp-Style)
```javascript
export const renderMessageStatusIcon = (message, currentUserId) => {
  // Only show status icons for messages sent by the logged-in user
  if (message.senderId !== currentUserId) return null;

  if (message.isSeen || message.isRead) {
    return <DoubleCheckmarkIcon color="#25D366" />; // Green or Blue double check
  }

  if (message.isDelivered) {
    return <DoubleCheckmarkIcon color="#8E8E93" />; // Grey double check
  }

  return <SingleCheckmarkIcon color="#8E8E93" />;   // Single grey check
};
```

### B. Chat Screen Lifecycle Flow
1. **On Screen Open:**
   - Call `GET /api/v1/conversations/:id/messages?limit=30` to load messages.
   - Emit `socket.emit("conversation:join", { conversationId })`.
   - Call `PATCH /api/v1/conversations/:id/seen` to mark unread messages as read.
   - Emit `socket.emit("message:seen", { conversationId })` for realtime update.
2. **On New Message Incoming via Socket (`message:new`):**
   - If the active screen is currently this conversation, immediately emit `message:seen` and `message:delivered`.
   - If user is in another screen, immediately emit `message:delivered` (so sender gets double grey check).
3. **On Screen Exit:**
   - Emit `socket.emit("conversation:leave", { conversationId })`.
